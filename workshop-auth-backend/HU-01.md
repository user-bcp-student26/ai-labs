# HU-01: Asegurar la integridad del token de autenticación

## Origen
- **H-AUTH-03** — `auth/src/main/java/com/bcp/workshop/auth/LegacyTokenUtil.java:8,12-15`
- **H-AUTH-04** — `auth/src/main/java/com/bcp/workshop/auth/LegacyTokenUtil.java:8`; `auth/src/main/resources/application.properties:4-7`

## Contexto
- El token se codifica en Base64, que no firma ni cifra el contenido. Incluye username, rol, expiración y un secreto, por lo que actualmente no acredita integridad criptográfica.
- El secreto está fijo en Java y CORS acepta cualquier origen. El alcance real del riesgo depende de cómo los clientes y consumidores usan el token.

## Ajustes necesarios
- Sustituir la codificación Base64 por un mecanismo que permita verificar criptográficamente la integridad del token.
- Eliminar el secreto fijo del código y definir una forma segura de proporcionarlo a la aplicación, sin incluir secretos en el repositorio.
- Reemplazar el origen CORS permisivo por orígenes explícitamente permitidos.

## Criterios de aceptación
- Una prueba unitaria confirma que un token emitido válido se verifica y que alterar username, rol o expiración hace que la verificación falle.
- Una prueba de configuración confirma que la aplicación obtiene el secreto desde configuración externa y que el código fuente no contiene un secreto fijo.
- Una prueba funcional confirma que CORS permite un origen configurado y no autoriza un origen no configurado.
- Las pruebas y sus reportes no imprimen tokens, secretos ni credenciales.

## Evidencia esperada
- Salida de las pruebas unitarias de emisión y verificación del token, incluidos los casos de contenido alterado.
- Salida de la prueba de configuración que demuestra que no se usa un secreto fijo en el código.
- Salida de pruebas funcionales de CORS para un origen permitido y otro no configurado.
- Revisión del cambio que confirme que la configuración y los logs no contienen valores sensibles.
